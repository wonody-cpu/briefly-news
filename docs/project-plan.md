# Briefly 프로젝트 기획서

## 1. 문제 정의

관심 분야의 최신 뉴스를 확인하려면 여러 뉴스 사이트나 포털을 각각 방문해야 한다. 이 과정에서 관심 없는 정보까지 반복해서 살펴보게 되고, 나중에 다시 읽고 싶은 기사를 체계적으로 보관하기도 어렵다.

Briefly는 사용자가 관심 주제를 선택해 관련 최신 뉴스를 한 화면에서 탐색하고, 필요한 기사를 북마크할 수 있도록 지원한다.

## 2. 개발 목적

- 여러 사이트를 방문하는 정보 탐색 과정을 줄인다.
- 사용자가 관심 있는 주제의 뉴스를 빠르게 확인하게 한다.
- 다시 읽고 싶은 기사를 브라우저에 간편하게 저장하게 한다.

## 3. 주요 사용자

- 광고·PR, 마케팅, 생성형 AI, 기업·브랜드, 문화·트렌드 뉴스에 관심 있는 대학원생
- 관심 분야의 뉴스를 짧은 시간에 훑어보고 필요한 기사를 따로 저장하고 싶은 사용자

## 4. 핵심 기능 요구사항

### 필수 기능(MVP)

1. 사용자는 관심 카테고리를 선택할 수 있다.
2. 앱은 선택한 카테고리의 최신 뉴스 목록을 표시한다.
3. 사용자는 제목 키워드로 현재 뉴스 목록을 검색할 수 있다.
4. 각 뉴스 카드에는 제목, 출처, 게시 시각, 요약 또는 설명, 원문 링크가 표시된다.
5. 사용자는 기사를 북마크에 추가하거나 제거할 수 있다.
6. 북마크는 브라우저를 닫았다가 다시 열어도 유지된다.
7. 사용자는 저장한 기사만 모아서 확인할 수 있다.
8. 로딩 중, 검색 결과 없음, 데이터 요청 실패 상태를 화면에 명확히 표시한다.
9. 앱은 컴퓨터와 모바일 화면에서 모두 사용할 수 있다.

### 선택 기능

- 기사 정렬 방식 변경
- 다크 모드
- 읽은 기사 표시
- 관심 카테고리 설정 저장

선택 기능은 필수 기능을 완성하고 테스트한 뒤 여유가 있을 때 구현한다.

## 7. 성공 기준

- 배포된 URL에서 최신 뉴스가 정상적으로 표시된다.
- 카테고리 선택과 키워드 검색이 정상 작동한다.
- 북마크 추가·삭제와 재접속 후 유지가 정상 작동한다.
- 오류가 발생해도 빈 화면 대신 사용자가 이해할 수 있는 안내가 표시된다.
- 다른 사람이 별도의 설명 없이 주요 기능을 사용할 수 있다.

## 9. 뉴스 데이터 및 기술 구성 결정

### 뉴스 데이터: GNews API

GNews API를 사용한다. 여러 언어와 국가의 뉴스를 구조화된 JSON으로 제공하고, 키워드 검색과 언어 설정을 지원하므로 관심 주제별 한국어 뉴스 앱에 적합하다.

- 무료 플랜: 일 100회 요청, 요청당 최대 10개 기사, 12시간 지연
- 교육 플랜: 심사를 거쳐 학생 과제에 무료 제공되며 일 1,000회 요청, 요청당 최대 25개 기사, 실시간 기사, 전체 CORS 지원
- API 키는 브라우저 코드에 넣지 않고 서버 측 환경 변수로 관리한다.
- 일일 요청 한도를 보호하기 위해 동일 요청 결과를 일정 시간 캐시한다.

### 앱 구조

- 프론트엔드: HTML, CSS, JavaScript 기반의 반응형 화면
- 서버 기능: Vercel 서버리스 함수가 GNews API를 호출
- 데이터 저장: 북마크와 사용자 설정은 브라우저 `localStorage`에 저장
- 배포: GitHub 저장소와 연결한 Vercel 배포

이 구성은 별도의 데이터베이스나 로그인 없이도 핵심 기능을 구현하며, API 키가 공개되는 문제와 배포 환경의 브라우저 요청 제한을 피할 수 있다.
