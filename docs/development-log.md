# AI 활용 및 문제 해결 과정 기록

이 문서는 개발 중 실제로 발견한 문제와 AI Coding Agent를 활용해 해결한 과정을 기록한다. 최종 보고서를 작성할 때 각 사례를 문제 상황, AI 활용, 해결 과정, 최종 결과의 네 항목으로 정리한다.

## 기획 단계

### 사례 1. 구현 가능성과 활용성을 함께 고려한 주제 선정

- **문제 상황:** 과제 주제를 정하지 못했고, 일상에서 사용할 수 있으면서도 개발 과정이 지나치게 어렵지 않은 앱이 필요했다.
- **AI 활용:** 전공, 실용성, 구현 난이도, 과제 평가 기준을 고려한 여러 아이디어를 요청하고 비교했다.
- **해결 과정:** 기록형 앱과 정보 제공형 앱을 비교한 뒤, 실제 활용성과 결과물의 완성도가 높은 관심 주제 뉴스 앱을 선택했다. 실시간 뉴스 앱은 외부 데이터 연결이 필요하므로 기능 범위를 핵심 기능 중심으로 제한하기로 했다.
- **최종 결과:** 관심 주제별 뉴스를 탐색하고 북마크하는 웹 앱 `Briefly`를 과제 주제로 선정했다.

## 개발 단계

### 사례 2. 배포 가능한 뉴스 API 선정

- **문제 상황:** 실시간 뉴스 앱은 외부 뉴스 데이터가 필요하지만, 일부 무료 API는 로컬 개발에서만 사용할 수 있거나 배포 환경에서 브라우저 요청을 차단한다. API 키를 프론트엔드에 직접 넣으면 외부에 노출되는 문제도 있다.
- **AI 활용:** NewsAPI, GNews API, Guardian Open Platform의 공식 문서를 비교해 학생 과제 사용 조건, 요청 한도, 한국어 뉴스 적합성, 배포 제약을 조사하도록 요청했다.
- **해결 과정:** NewsAPI 무료 플랜은 배포 환경 사용이 불가능하고, Guardian API는 한 언론사의 영문 콘텐츠 중심이므로 제외했다. GNews API는 학술·비상업 용도로 사용할 수 있고 별도의 교육 플랜도 제공하므로 선택했다. API 키는 서버리스 함수의 환경 변수에 저장하고, 프론트엔드는 이 함수를 통해서만 뉴스를 요청하도록 설계했다.
- **최종 결과:** GNews API와 Vercel 서버리스 함수를 사용하는 구조를 결정했다. 동일 요청 캐시와 명확한 오류 화면도 구현 범위에 포함했다.

### 사례 3. 한국어 키워드 검색 결과가 표시되지 않는 문제

- **문제 상황:** API 키를 연결한 뒤 앱을 실행했지만 광고·마케팅 카테고리의 기사 수가 0건으로 표시되었다. 검색식을 단순한 한국어 단어로 바꿔도 GNews Search API가 빈 결과를 반환했다.
- **AI 활용:** API 인증 실패와 검색식 문제를 구분하기 위해 응답 상태, 기사 수, 여러 카테고리와 별도 엔드포인트의 결과를 단계적으로 비교하도록 요청했다.
- **해결 과정:** Search API는 정상 상태 코드와 함께 0건을 반환했지만 Top Headlines API는 같은 키와 한국어 설정으로 10건을 정상 반환했다. 안정적인 앱을 위해 공식 주요 뉴스 카테고리를 사용하고, 키워드 검색은 받아온 뉴스의 제목과 설명을 브라우저에서 필터링하는 방식으로 변경했다.
- **최종 결과:** 주요 뉴스, 비즈니스·브랜드, 기술·AI, 문화·콘텐츠, 과학의 5개 카테고리에서 한국어 기사를 안정적으로 제공하는 구조로 개선했다.

### 사례 4. 일부 방송사 기사의 제목이 언론사명으로 표시되는 문제

- **문제 상황:** KBS 기사 일부의 제목이 실제 기사 제목이 아니라 `KBS 뉴스`로 표시되어 카드만 보고 기사 내용을 구분할 수 없었다.
- **AI 활용:** GNews가 반환한 원본 제목, 출처, 설명 데이터를 비교하고 실제 기사 제목을 대신할 수 있는 안전한 표시 규칙을 요청했다.
- **해결 과정:** 기사 제목이 출처명과 같거나 짧은 방송사명뿐인 경우를 감지하고, 기사 설명의 첫 문장을 최대 72자로 정리해 카드 제목으로 사용하는 보정 함수를 추가했다. 정상적인 기사 제목은 그대로 유지했다.
- **최종 결과:** 일반 기사의 제목을 변경하지 않으면서, 제목 정보가 부정확한 방송사 기사도 내용을 구분할 수 있게 되었다.

### 사례 5. 새로고침 후 북마크 목록이 비어 보이는 문제

- **문제 상황:** 북마크 개수는 브라우저 저장소에서 복원되지만 저장한 기사 화면에는 기사가 나타나지 않는 경우가 있었다.
- **AI 활용:** 저장 데이터 복원, 검색 필터, 비동기 뉴스 요청과 저장 목록 전환 흐름을 점검하도록 요청했다.
- **해결 과정:** 저장 목록을 열 때 이전 검색어가 저장 기사에도 적용될 수 있는 흐름을 발견했다. 저장 목록에서는 검색 필터를 적용하지 않고, 목록을 열 때 검색 상태와 입력창을 초기화하도록 수정했다. 저장 데이터도 유효한 기사만 복원하도록 보강했다.
- **최종 결과:** 새로고침 후 저장 개수가 복원되면 저장 목록에서 전체 북마크 기사가 표시되도록 개선했다.

### 사례 6. 저장 기사 화면의 카테고리 탭이 일반 뉴스로 전환되는 문제

- **문제 상황:** 저장한 기사 화면에서도 주요 뉴스, 비즈니스·브랜드 등의 카테고리 탭이 표시되었고, 탭을 누르면 저장 기사 필터가 해제되어 일반 뉴스 화면으로 전환되었다.
- **AI 활용:** 저장 기사 화면에서 카테고리 탭을 제거하거나 저장 기사만 분류하는 방식 중 현재 데이터 구조에 적합한 화면 흐름을 검토하도록 요청했다.
- **해결 과정:** 기존 북마크에는 카테고리 정보가 없는 경우가 있어 잘못된 분류 기능을 추가하는 대신, 저장 기사 화면에서는 카테고리 탭을 숨겼다. 검색창은 유지하되 저장 화면에서는 저장한 기사만 검색하도록 동작과 안내 문구를 변경했다.
- **최종 결과:** 사용자가 저장 기사 목록을 보고 있는 동안 일반 뉴스 화면으로 의도치 않게 전환되지 않으며, 저장한 기사는 별도로 검색할 수 있다.

추가 사용자 테스트에서 우측 상단 버튼을 다시 눌러야만 일반 뉴스로 돌아갈 수 있어 복귀 동작을 발견하기 어렵다는 의견이 있었다. 이에 저장 기사 제목 바로 아래에 `← 전체 뉴스로 돌아가기` 버튼을 추가해 현재 콘텐츠와 가까운 위치에서도 명확하게 복귀할 수 있도록 개선했다.

### 사례 7. 첫 Vercel 배포에서 전체 페이지가 500 오류를 반환한 문제

- **문제 상황:** Vercel Production 배포는 완료 상태였지만 공개 URL의 첫 화면과 뉴스 API가 모두 `FUNCTION_INVOCATION_FAILED` 500 오류를 반환했다.
- **AI 활용:** 실제 공개 URL의 HTTP 상태, 오류 본문, Vercel 빌드 로그를 비교해 로컬에서는 발생하지 않는 배포 환경 문제를 진단하도록 요청했다.
- **해결 과정:** 빌드 로그에서 Vercel이 브라우저용 `app.js`를 Node 서버의 루트 진입점으로 잘못 감지한 사실을 확인했다. `vercel.json`에서 프레임워크를 `Other`에 해당하는 `null`로 명시하고 자동 빌드 명령을 껐다. 첫 수정에서 지정한 Node.js 20은 Vercel에서 지원이 종료됐다는 추가 오류가 발생해 현재 지원되는 Node.js 24로 변경했다.
- **최종 결과:** 수정된 구성으로 재배포한 결과 공개 페이지와 뉴스 API가 모두 HTTP 200을 반환했고, 한국어 주요 뉴스 10건도 정상적으로 표시되었다.

### 사례 8. 뉴스 모음과 브리핑의 차이가 부족한 문제

- **문제 상황:** 앱의 문구는 뉴스를 간결하게 제공한다고 설명하지만, 실제 카드에는 뉴스 제목과 원본 설명만 보여 일반적인 뉴스 모음처럼 느껴졌다.
- **AI 활용:** 별도의 유료 AI API를 추가하지 않으면서도 사용자가 기사 핵심을 빠르게 파악할 수 있는 개선 방법을 요청했다.
- **해결 과정:** GNews가 제공하는 기사 설명에서 언론사 표기와 불필요한 공백을 제거하고 첫 핵심 문장을 추출하는 함수를 추가했다. 결과는 각 카드의 `핵심 한 줄` 영역에 시각적으로 구분해 표시하며, 문장이 중간에 잘리지 않도록 전체를 보여준다.
- **최종 결과:** 사용자는 원문을 열기 전에 카드에서 기사의 핵심 내용을 짧게 훑어볼 수 있게 되었다. 이 기능은 생성형 AI 요약이 아니라 제공된 기사 설명을 규칙에 따라 간결하게 정리하는 방식이므로 추가 비용이나 별도 API가 필요하지 않다.

첫 구현은 한 화면에 3개의 카드가 나란히 배치되어 핵심 한 줄이 여러 줄로 잘렸다. 사용자 피드백에 따라 목록을 세로형 뉴스 피드로 변경했다. 데스크톱에서는 왼쪽에 뉴스 이미지, 오른쪽에 제목과 잘리지 않는 핵심 한 줄을 배치하고, 모바일에서는 이미지와 내용을 위아래로 쌓아 가독성을 유지했다.

### 사례 9. 원하지 않는 뉴스 출처가 함께 표시되는 문제

- **문제 상황:** 여러 출처를 제공하는 GNews 특성상 사용자가 익숙하지 않거나 선호하지 않는 `GameGPU` 등의 출처도 뉴스 목록에 함께 표시되었다.
- **AI 활용:** 특정 언론사를 임의로 삭제하지 않으면서 사용자가 출처를 직접 선택할 수 있는 필터 기능을 요청했다.
- **해결 과정:** 현재 카테고리 또는 저장 기사 목록에 실제로 포함된 언론사명을 수집해 `전체 출처` 드롭다운을 자동 생성했다. 출처를 선택하면 검색어 조건과 함께 적용되고, 카테고리가 변경되면 출처 목록도 새 데이터에 맞춰 초기화되도록 구현했다.
- **최종 결과:** 사용자는 전체 뉴스를 보거나 원하는 언론사의 기사만 골라볼 수 있게 되었다.

### 사례 10. 앱 소개 문구와 실제 뉴스 카테고리가 일치하지 않는 문제

- **문제 상황:** 상단 소개는 광고·마케팅, AI, 문화를 강조했지만 실제 앱은 주요 뉴스, 비즈니스·브랜드, 기술·AI, 문화·콘텐츠, 과학 카테고리를 제공해 설명과 콘텐츠 사이에 차이가 있었다.
- **AI 활용:** 카테고리를 더 세분화하는 방법과 소개 문구를 실제 데이터에 맞추는 방법을 비교하도록 요청했다.
- **해결 과정:** GNews가 안정적으로 지원하는 공식 카테고리를 유지하고, 빈 검색 결과가 발생할 수 있는 임의의 세부 카테고리를 추가하는 대신 소개 문구를 실제 제공 범위에 맞게 수정했다.
- **최종 결과:** 사용자가 첫 화면에서 기대하는 뉴스 분야와 실제 탐색할 수 있는 카테고리가 일치하게 되었다.

### 사례 11. 모바일 캡처에서 오른쪽 내용이 잘리는 문제

- **문제 상황:** 제출용 모바일 화면을 캡처해 검토한 결과, 일부 긴 제목과 콘텐츠 때문에 페이지 폭이 모바일 화면보다 넓어져 오른쪽 내용이 잘렸다.
- **AI 활용:** 실제 모바일 해상도의 캡처를 점검하고 가로 넘침을 유발할 수 있는 그리드와 긴 텍스트 처리 방식을 수정하도록 요청했다.
- **해결 과정:** 페이지와 뉴스 그리드의 최대 폭을 화면 너비로 제한하고, 그리드 열과 카드 본문에 `min-width: 0`을 적용했다. 긴 영문·숫자 조합의 제목과 핵심 문장도 필요한 위치에서 줄바꿈되도록 보강했다.
- **최종 결과:** 모바일에서도 페이지가 좌우로 밀리지 않고 뉴스 카드 전체 내용을 화면 안에서 읽을 수 있도록 개선했다.

실제 구현과 테스트 중 발견되는 사례를 계속 추가할 예정이다.
